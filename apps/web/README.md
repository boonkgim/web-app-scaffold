# @web-app-scaffold/web

The Next.js app, deployed to Cloudflare Workers via [OpenNext](https://opennext.js.org/cloudflare).
Part of the [web-app-scaffold](../../README.md) workspace — see the root README for the
stack, and for how to bring the whole thing up.

```bash
pnpm dev          # next dev on http://localhost:3000
pnpm preview      # build with OpenNext and run it on workerd locally
pnpm codegen      # Cloudflare + Next route types, then typed GraphQL documents
```

`pnpm dev` alone is not the whole app: pages read data from `apps/graphql` over the `API`
service binding, so run `pnpm dev` from the repository root to start both.

## What is particular to this package

- **This app owns the theme.** Every token value lives in `src/styles/theme.css`, and no
  component names a colour — Tailwind palette utilities in `className` are an ESLint error
  outside `src/components/ui`, which is a vendored shadcn checkout. A re-theme is one file.
- **It never touches the database.** `packages/db` and `packages/email` are not
  dependencies of this package, so this Worker holds no database or mail credential.
- **GraphQL types are generated, not written.** `codegen` reads the API's merged
  `schema.generated.graphqls` and emits typed documents into `src/generated/`. Do not edit
  those by hand.
- **`NEXT_PUBLIC_*` variables are build inputs.** They are inlined by `next build`, so
  changing one needs a rebuild and redeploy — unlike the API's secrets, which are runtime
  values.
- **`AGENTS.md` is generated by `next dev`** and re-added if removed. Commit it with your
  work rather than fighting it.

See `.claude/skills/project-web/SKILL.md` and `.claude/skills/project-ui/SKILL.md` for the
full conventions.
